## 세 줄로 먼저 읽기

- Ollama는 모델 그 자체가 아니라 모델을 실행하도록 돕는 도구다.
- 다운로드 크기와 실행 중 필요한 메모리는 다르다. 작은 모델로 먼저 확인한다.
- 로컬 도구를 쓴다고 모든 데이터가 자동으로 로컬에만 남는 것은 아니다.

## 플레이어와 동영상 파일을 구분하듯

동영상을 보려면 플레이어와 영상 파일이 각각 필요하다. Ollama와 Llama·Gemma 같은 모델의 관계도 비슷하다. Ollama를 설치한 것만으로 원하는 모델의 파일까지 준비된 것은 아니다. 선택한 모델을 내려받고 실행해야 한다.

클라우드 API가 식당에 음식을 주문하는 방식이라면, 로컬 실행은 재료와 조리 도구를 집에 준비하는 방식이다. 호출당 외부 API 요금을 내지 않는 대신 내 컴퓨터의 메모리, 저장 공간, 전력과 관리 시간이 들어간다. “로컬은 공짜”보다는 **비용이 발생하는 위치가 달라진다**고 이해하는 편이 정확하다.

## 처음에는 모델 크기보다 실행 가능 여부부터

원 메모에는 강사 컴퓨터의 다운로드 크기와 응답 시간이 나온다. 이 숫자를 모든 컴퓨터의 기준으로 옮길 수는 없다. 모델의 정밀도, 문맥 길이, 장치와 동시 실행 작업에 따라 필요한 메모리와 속도가 달라지기 때문이다.

<div class="post-table-scroll" role="region" aria-label="로컬 모델 실행 전 확인할 것" tabindex="0">

| 확인 대상 | 쉬운 뜻 | 놓치기 쉬운 점 |
| --- | --- | --- |
| 저장 공간 | 모델 파일을 보관할 자리 | 모델을 여러 개 받으면 합산된다. |
| RAM·GPU 메모리 | 실행 중 작업할 자리 | 다운로드 파일 크기와 같지 않다. |
| 문맥 길이 | 한 번에 펼쳐 놓을 자료량 | 자료가 길어지면 메모리 부담도 커질 수 있다. |
| 모델 라이선스 | 사용·배포에 관한 조건 | 가중치 공개와 모든 용도의 무제한 사용은 다르다. |

</div>

양자화는 모델 숫자를 더 낮은 정밀도로 표현해 메모리 부담을 줄이는 방법이다. 사진 용량을 줄이는 비유가 도움이 되지만 실제 JPEG 압축과 같은 알고리즘은 아니다. 크기와 품질의 균형을 직접 확인해야 한다.

## 목록 확인 → 다운로드 → 실행

Ollama를 설치하고 실행한 환경에서 다음처럼 진행할 수 있다. `llama3.2:1b`는 원 메모에 등장하는 작은 모델을 사용한 예시이며 최신·최고 성능 모델이라는 뜻은 아니다. 다운로드에는 네트워크와 저장 공간이 필요하다.

```bash
ollama list
ollama pull llama3.2:1b
ollama run llama3.2:1b
```

첫 명령은 설치된 모델을 보고, 두 번째는 해당 모델을 내려받으며, 세 번째는 대화를 시작한다. 설치와 실행 방법은 [Ollama 공식 빠른 시작](https://docs.ollama.com/quickstart)에서 운영체제에 맞춰 확인할 수 있다. 이 글을 작성하면서 사용자 컴퓨터에 모델을 설치하거나 다운로드하지는 않았다.

`localhost`는 현재 컴퓨터 자신을 가리키는 주소다. Ollama의 OpenAI 호환 경로는 로컬 서버가 실행 중이라면 `http://localhost:11434/v1/` 형태로 사용한다. 원 메모의 코드에 보이던 주소 주변의 `< >`는 실제 URL에 넣는 문자가 아니다. [Ollama 호환 API 문서](https://docs.ollama.com/api/openai-compatibility)

## 로컬이라는 이름보다 데이터가 가는 곳 보기

로컬 모델을 이미 내려받았고 외부 도구를 사용하지 않는다면, 추론을 내 컴퓨터에서 처리할 수 있다. 반대로 클라우드 모델을 선택하거나 검색·외부 API 도구를 연결하면 데이터가 외부로 나갈 수 있다. 모델 실행 위치와 도구의 통신 경로를 함께 확인해야 한다.

<div class="post-table-scroll" role="region" aria-label="로컬 실행의 흔한 오해" tabindex="0">

| 흔한 생각 | 확인할 사실 |
| --- | --- |
| Ollama면 항상 오프라인이다 | 선택한 모델이 로컬인지, 외부 서비스가 연결됐는지 확인한다. |
| 서버 주소가 겹치면 고장이다 | 같은 포트를 다른 프로세스가 사용하는지 확인한다. |
| 큰 모델이면 항상 더 낫다 | 실제 질문에서 정확도와 응답 시간을 비교한다. |
| 키 자리에 아무 값이나 넣어도 안전하다 | 기본 로컬 호환 예시의 편의일 뿐, 외부 공개 서버의 인증 설계가 아니다. |

</div>

## 작은 실험으로 판단하기

가상의 동네 행사 안내문을 한 문단 넣고 세 줄로 요약하게 해 보자. 날짜가 유지되는지, 없는 내용을 만들지 않는지, 기다릴 만한 속도인지 확인한다. 그 다음 조금 더 긴 문서로 바꾼다. 처음부터 대형 모델과 긴 문서를 동시에 사용하면 무엇 때문에 느려졌는지 구분하기 어렵다.

로컬 모델을 선택하는 이유는 단순한 벤치마크 우승이 아닐 수 있다. 오프라인 사용, 실행 환경 통제, 실험의 자유도처럼 필요한 조건을 먼저 정하면 선택이 쉬워진다.
